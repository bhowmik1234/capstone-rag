# Healthcare Dataset Overview (Synthea FHIR)

This project utilizes a synthetic clinical dataset generated by **Synthea**, an open-source patient population simulator. The data follows the **HL7 FHIR (Fast Healthcare Interoperability Resources)** standard and is provided in **NDJSON (Newline Delimited JSON)** format for efficient bulk processing.

---

## Dataset Statistics
- **Population Size**: 10 Patients
- **Format**: NDJSON
- **Standard**: HL7 FHIR US Core Profiles
- **Origin**: [Synthea Patient Simulator](https://github.com/synthetichealth/synthea)

---

## Included FHIR Resource Types

The RAG pipeline processes the following core medical resources to build its knowledge base:

| Resource Type | Description | Key Fields Used |
| :--- | :--- | :--- |
| **Patient** | Demographics and identity. | Name, Gender, Birth Date, ID |
| **Condition** | Diagnoses, problems, or health concerns. | Clinical Status (Active/Resolved), Onset Date, Code |
| **Observation** | Vital signs (BP, Heart Rate), labs, and measurements. | Value, Units, Effective DateTime, Category |
| **MedicationRequest** | Prescriptions and medication orders. | Medication Name, Authored On, Status |
| **AllergyIntolerance** | Records of clinical allergies or sensitivities. | Substance, Criticality, Type |
| **Procedure** | Clinical actions performed on the patient. | Procedure Name, Date, Performed Period |
| **Encounter** | Interactions between a patient and healthcare provider. | Type, Period, Reason |
| **DiagnosticReport** | Results of lab tests and imaging. | Conclusion, Issued Date, Result Links |

---

## Data Processing Workflow

1.  **Ingestion**: The `src/scripts/ingest.ts` script reads the NDJSON files from the source directory.
2.  **Normalization**: Each FHIR resource is flattened into a simplified string representation suitable for LLM consumption (e.g., `"Patient X was diagnosed with Y on Date Z"`).
3.  **Embedding**: These strings are converted into 768-dimensional vectors using the `nomic-embed-text` model.
4.  **Vector Storage**: The vectors and their corresponding text are stored in **LanceDB** with metadata filtering for `patientId` and `resourceType`.

---

## Privacy and Security Note
While the dataset follows the real-world FHIR schema, **all data is 100% synthetic**. No real Protected Health Information (PHI) is contained within this repository or the search results. This allows for safe research and testing of LLM logic without HIPAA privacy risks.
